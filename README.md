# Курс "AI-инструменты в жизни инженера: от идеи до продакшена" | ИТМО

## 📋 О курсе

Практический курс, который учит системно применять AI-инструменты на всех этапах жизненного цикла разработки ПО. Курс идёт потоком, практики проходят в группах.

**Основа курса:** каждый AI-инструмент привязан к реальному этапу разработки: требования → дизайн → реализация → тестирование → CI/CD → эксплуатация.

**Сквозной проект:** вы ведёте свой проект от идеи до фичи в продакшен-стиле — с User Stories, DoR/DoD, архитектурой, тестами и CI. Каждая неделя добавляет новый слой.

**Финальная цель:** мышление «AI-augmented engineer»: инженер, который проектирует и автоматизирует процессы разработки, выступая архитектором и техническим руководителем для своих AI-ассистентов.

**Итоговая аттестация:** презентация финального проекта с AI-обвязкой (20 баллов) и защита дизайна (30 минут).

## 🎯 Философия курса

> **Фундаментальный сдвиг роли инженера: от исполнителя к архитектору**

**Роль на курсе: архитектор и тимлид для AI.**

1. **Проектируете задачи** через промпт-инжиниринг
2. **Управляете контекстом** через MCP, скиллы и структуру знаний
3. **Проводите строгое код-ревью** сгенерированного кода
4. **Автоматизируете процессы разработки**, включая сам код

### Ключевые принципы

- **Единая линия курса:** сквозная структура от первой лекции до финального проекта, без разрывов между темами
- **Проектно-ориентированное обучение:** свой сквозной проект через весь курс
- **Итеративное углубление:** от простых запросов к профессиональным техникам на тех же задачах
- **От локального к глобальному контексту:** от `@file` до полноценного MCP и скиллов
- **Constitution-driven development:** у проекта есть «конституция» (`.specify/memory/constitution.md`): неизменяемые принципы (язык, TDD, Library-First, CLI, integration testing)
- **Проверяемость и воспроизводимость:** каждый результат фиксируется артефактами (Markdown/диаграммы/тесты), код живёт в репозитории с понятными правилами (`AGENTS.md`, `specs/`)

## 🧰 Инструменты и «рабочее место инженера»

- **Universal LLMs:** deepseek, доступ через OpenRouter (единая точка доступа к разным моделям)
- **Coding agents:** Cursor / VSCode + Roo Code (agentic-разработка в IDE)
- **Хранение артефактов:** GitHub, текстовые доки в папке `product`, обязательный Makefile для домашек
- **Оркестрация и автоматизация:** N8N (локально или в облаке) для workflow и интеграций
- **Инженерный контур:** GitHub (Issues/PR), GitHub Actions (CI/CD), PlantUML (диаграммы), pytest/coverage (тестирование)

## 📚 Структура курса

Лекция и практика проходят раз в неделю: день лекции, день практики. Приёмка домашних заданий — отдельными окнами между темами, часть синхронно, часть асинхронно (с опциональной консультацией).

**Практика 1. Проект: знакомим с техническими бизнес-контекстами**

**Результат:** сформулированная идея проекта: требования, продуктовый и технический план.

**Домашка 1:** подготовить первые артефакты проекта и наметить, какой этап своей работы можно оптимизировать через AI.

### Лекция 2: LLM и промпт-инжиниринг. Введение в агенты

Обзор AI в мире, промт-техники (R.C.T.F., Chain of Thought), эволюция агентских систем, тренды 2026–2030, обзор кодинг-агентов на уровне класса инструментов (Roo Code разбирается отдельно, в практике).

**Практика 2. Дорабатываем артефакты для программирования логики**

**Результат:** доработанные артефакты проекта: User Stories, DoR/DoD, архитектурная схема, acceptance criteria, test suite.

**Домашка 2:** доработать артефакты по итогам ревью.

**Приёмка ДЗ 1–2:** асинхронно, с опциональной консультацией по вопросам.

## 🧪 Формат практик и семинаров

- **Лекция:** фокус и контекст темы, часто с примерами из практики Авито.
- **Практика:** групповая работа: разбор артефактов (User Stories, DoR/DoD, AC, test plan) и реализация куска функциональности сквозного проекта, через цикл «контекст → задача → ревью → уточнение».

## 📝 Домашние задания и приёмка

- **Фича-итерации:** реализовать очередную User Story из своего бэклога. На 5-й неделе задание учитывает Spec-Driven подход.
- **Тестирование:** добавить API-тесты или e2e-тесты на ключевые сценарии.
- **CI/CD:** добавить в pipeline матрицу сборки.
- **Ассистент:** дописать оценку сложности тикета и фильтр пул-реквестов.

Критерии приёмки объявляются заранее по каждой практике. Формат приёмки (синхронный или асинхронный с опциональной консультацией) свой для каждого ДЗ: конкретные окна смотрите в расписании курса.

## 🏆 Оценивание

На курсе стобалльная система:

- 10 баллов за каждую домашку (80 баллов в сумме)
- 20 баллов за экзамен

Также можно получить дополнительные баллы:

- +1 балл за активность на практиках 
- +2 балла за нестандартное решение на каждой сдаче домашних работ

Если вы набираете больше 100 баллов в сумме, то в итоговую ведомость пойдет ровно 100.

Можно получить -2 балла, если работа сдана позже дедлайна.
