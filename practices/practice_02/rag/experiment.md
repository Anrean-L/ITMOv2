вход и необходимые заглушки;

ожидаемые вызовы или отсутствие вызовов обработчика секретов и LLM;

Для значений ниже и на границе не утверждай, что один только

и успешный ответ заглушки должны быть заданы явно.

- Вывод из нескольких фрагментов:

[adr.md → Архитектурная схема](../../practice_01/adr.md#архитектурная-схема); также «Валидацию входа и ограничение длины diff ... (API-1).   - При превышении лимита: отклонение 413; при ok — дальнейшие шаги (редактор секретов → LLM). Support: [CASE.md](../../practice_01/CASE.md#правила-репозитория), [adr.md → Архитектурная схема](../../practice_01/adr.md#архитектурная-схема)

- Источник не определяет:
  - Что именно считать «Unicode-символом» для подсчёта длины: кодовая точка или графемный кластер — в источниках не указано; отмечено как открытый вопрос.

Не вводить дополнительных ограничений по строкам — источники их не задают. Открытые вопросы: метод подсчёта Unicode-символов; байты/токены LLM не используются для этого лимита. Support: [adr.md → Архитектурная схема](../../practice_01/adr.md#архитектурная-схема), [CASE.md](../../practice_01/CASE.md#правила-репозитория), [tests_e2e.md](../../practice_01/tests_e2e.md#e2e-проверки).

## Что изменили в исходном артефакте

- Файл и раздел:
  - [practice_01/adr.md → «API-1: уточнение лимита diff»](../../practice_01/adr.md#api-1-уточнение-лимита-diff) — добавлены адресные уточнения (что проверяется; когда; трактовка превышения; действия, которые не выполняются после отклонения; открытые вопросы про Unicode/байты/токены; без новых ограничений по строкам).
  - [practice_01/tests_integration.md → «API-1: сценарии размера diff (integration)»](../../practice_01/tests_integration.md#api-1-сценарии-размера-diff-integration) — уточнены сценарии: 19999, 20000, 20001 (с проверкой нулевых вызовов редактора/LLM), и точный случай «diff = "token=" + "A" * 20004» с арифметической демонстрацией гипотетического сокращения при маскировании.
- Изменение:
  - Уточнён порядок применения API-1: проверка исходного `diff` до маскирования секретов; поведение на границе и при превышении; запрет последующих действий при отклонении; прояснены открытые вопросы о понятии «Unicode-символа», и что байты/токены LLM не подменяют лимит в символах; не вводились дополнительные ограничения по строкам.
- Как проверили ссылки (проверки документации, не тесты сервиса):
  - Проверены существование файлов и заголовков: [CASE.md → «Правила репозитория»](../../practice_01/CASE.md#правила-репозитория), [adr.md → «Решение»](../../practice_01/adr.md#решение), [adr.md → «Архитектурная схема»](../../practice_01/adr.md#архитектурная-схема), [tests_e2e.md → «E2E-проверки»](../../practice_01/tests_e2e.md#e2e-проверки), [tests_integration.md → «Integration-проверки»](../../practice_01/tests_integration.md#integration-проверки), [adr.md → «API-1: уточнение лимита diff»](../../practice_01/adr.md#api-1-уточнение-лимита-diff), [tests_integration.md → «API-1: сценарии размера diff (integration)»](../../practice_01/tests_integration.md#api-1-сценарии-размера-diff-integration).
