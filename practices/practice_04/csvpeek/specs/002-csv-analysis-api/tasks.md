**Input**: [spec.md](spec.md), [plan.md](plan.md), [research.md](research.md), [data-model.md](data-model.md), [HTTP](contracts/http-api.md), [quickstart.md](quickstart.md), [принятый контракт](../ui-backend-contract.md).

**Правила**: задачи ниже предназначены для будущей реализации. Изменения кода и тестов выполнять через `apply_patch`, проверять результат автоматического хука и исправлять ошибки. Тесты пишутся до соответствующей реализации и сначала должны обнаруживать отсутствие поведения.

## Dependencies & Execution Order

- Setup T001–T002 → foundation T003–T005 → US4 T006–T009 → US1 T010–T015 → US2 T016–T021 → US3 T022–T028 → итоговые проверки T029–T033. US4 предшествует работающему HTTP API, чтобы промежуточный срез не нарушал контракт безопасности.
- Независимые тесты US1, US2 и US3 можно подготовить после foundation и соответствующих интерфейсов-заглушек; реальные HTTP-тесты ошибок и кэша зависят от US1 и US2 соответственно. Одна и та же история проверяется самостоятельно на соответствующем наборе запросов, хотя её сквозное выполнение использует общую основу и готовые предыдущие слои.
- T029 и T030 затрагивают отдельные файлы и могут готовиться параллельно после стабилизации поведения; фактический бенчмарк и итоговая приёмка выполняются после интеграции. Задачи в `src/csvpeek/server.py` последовательны.

## Parallel Examples

- **US4**: T006 и T007 готовят независимые файлы тестов; затем последовательно T008 и T009.
- **US1**: T010 и T011 готовят тесты анализа и HTTP в разных файлах; затем T012–T015.
- **US2**: T016 и T017 готовят тесты анализа и HTTP независимо; затем T018–T021.
- **US3**: T022, T023 и T024 готовят разные наборы проверок; затем T025–T028 последовательно.

## Implementation Strategy

Безопасный первый сквозной срез: setup, foundation, US4 и US1; демонстрировать его только как промежуточный, поскольку ошибки и обязательный LRU ещё не завершены. Затем выполнить US2 и US3, совместную проверку с UI и сквозные проверки. Полная готовность определяется всеми историями, проверками безопасности, регрессией CLI и результатом `./scripts/check.sh`; бенчмарк фиксирует измерения без обязательного порога.
