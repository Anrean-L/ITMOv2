# HTTP-интерфейс бэкенда

Нормативный общий контракт — [specs/ui-backend-contract.md](../../ui-backend-contract.md); этот документ фиксирует его применение к реализации бэкенда, не изменяя контракт.

- Слушать IPv4 `127.0.0.1`, один HTTP-origin для UI и API. Проверять единственный `Host` на всех маршрутах, необязательный `Origin` — на точный origin; `null`, повтор и некорректные значения запрещены. Учитывать порт 80; не использовать forwarded-заголовки.
- `POST /api/analysis`: ровно один `X-Csvpeek-Request: 1`, ровно одна файловая часть `file` в `multipart/form-data`. Проверки безопасности предшествуют чтению тела, анализу и кэшу. Нарушения — 403 без пользовательских данных; формат тела не определён; cross-origin CORS-разрешений нет.
- Успех 200, UTF-8 JSON: `{"row_count":1,"column_count":2,"columns":[{"name":"x","missing_count":1},{"name":"x","missing_count":0}]}`. Позиция — порядок массива; имя файла отсутствует. Инварианты и лимиты — в [модели](../data-model.md).
- Ошибки приложения: `{"error":{"code":"…","message":"…","details":{}}}`. `400 invalid_request`, `415 unsupported_media_type`, `413 limit_exceeded`, `422 empty_csv`, `422 invalid_encoding`, `422 invalid_structure`, `500 internal_error`; другие методы — 405 после проверок безопасности, тело 405 не определено. Для 403 схема не фиксирована.
- При неверной ширине `details` содержит целые `record`, `expected_fields`, `actual_fields`; для предела — `kind`, целое `limit`, `unit`. Виды: `file_bytes`/`bytes`, `columns`/`columns`, `rows`/`rows`, `field_bytes`/`bytes`. Код и статус определяются первой обнаруженной ошибкой после проверок безопасности; размер файла проверяется до разбора.
- Нет гарантии ответа при разрыве; после полной загрузки обработка может завершиться. Вне приложения ответы инфраструктуры могут не соответствовать JSON-схеме. Для деталей используйте принятый контракт.
