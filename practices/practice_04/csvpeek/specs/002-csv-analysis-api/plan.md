# Implementation Plan: Локальный бэкенд анализа CSV

**Branch**: `practice-5` | **Date**: 2026-10-27 | **Spec**: [spec.md](spec.md)

**Input**: `specs/002-csv-analysis-api/spec.md` и [принятый контракт](../ui-backend-contract.md). Скрипт setup сообщил идентификатор `002-csv-analysis-api`; фактическая текущая ветка — `practice-5`.

## Summary

Добавить отдельно запускаемый локальный HTTP-сервис, принимающий один CSV и возвращающий упорядоченную статистику, совместимую с CLI. Анализ отделён от HTTP и UI; успешные результаты переиспользуются в ограниченном LRU по SHA-256 исходных байтов. Безопасность и ответы следуют принятому контракту. Реализация этим планом не выполнялась.

## Technical Context

**Language/Version**: Python 3.12+.

**Primary Dependencies**: стандартная библиотека: `http.server`, `csv`, `hashlib`, `collections`, `threading` и средства MIME `email`. Пригодность multipart-разбора доказать тестами; сторонняя зависимость допустима только при доказанной необходимости и обосновании.

**Storage**: только оперативная память; без персистентных файлов, дисковых буферов и записи пользовательских данных в журналы.

**Testing**: `unittest`, существующий `./scripts/check.sh`, интеграционные HTTP и браузерные проверки; отдельный бенчмарк.

**Target Platform**: локальная машина, IPv4 loopback, один origin для UI и API.

**Project Type**: существующий CLI плюс независимый локальный HTTP-сервис; UI реализует другая команда.

**Performance Goals**: измерить прогретые и некэшированные запросы по FR-012; порог ускорения не задан.

**Constraints**: CSV до 10 МиБ, 1000 колонок, 100 000 записей, поле до 128 КиБ UTF-8 после разбора; кэш до 128 результатов и 16 МиБ сериализованного JSON. Тайм-аут и лимит конкуренции не определены, произвольные значения не вводятся.

**Scale/Scope**: локальное использование на одном устройстве; допускаются параллельные независимые запросы. Без публичного сервиса, многопользовательского режима и межустройственного доступа.

## Constitution Check

**Перед исследованием: PASS.** Сохранить CLI и его проверки; Python 3.12+ и стандартная библиотека; логика без UI; контракт согласован; предусмотреть позитивные, негативные и регрессионные тесты; детерминированные результаты и явные ошибки; не менять конфигурацию агента. Перед реализацией CSV-функциональности использовать `csv-feature-workflow`, `inspect_csv` на соответствующем примере и `apply_patch` для кода и тестов, проверить автоматический хук. В конце выполнить `./scripts/check.sh`.

**После проектирования: PASS при выполнении условий.** Контракт сохранён без новых внешних полей; HTTP и кэш не меняют CLI. Границы multipart, байтовый лимит и отсутствие дисковых временных копий подтверждаются тестами. Браузерные проверки нельзя считать пройденными без фактической проверки. Потребность во внешней зависимости требует обоснования и сравнения альтернатив.

## Delivery Design

1. Зафиксировать регрессию CLI и инспектировать примеры CSV. Выделить общую семантику так, чтобы старые сообщения и поведение CLI сохранились; HTTP-лимиты не применяются к CLI. Проверить пустые и повторные имена, многострочные записи и ошибки.
2. Реализовать независимый анализ исходных байтов, строгий UTF-8 и CSV, структурированные ошибки и проверки лимитов. Проверять байты поля после распаковки; не менять глобальный `csv.field_size_limit` во время конкурирующих запросов. Следовать спецификации при выборе первой ошибки.
3. Реализовать кэш с блокировкой метаданных и ожиданием результата для каждого ключа: разбор вне общей блокировки, ошибки будят ожидающих и не сохраняются. Результат неизменяем или копируется; размер — байты сериализованного JSON. Проверить eviction по обоим лимитам и граничные гонки.
4. Подключить HTTP: loopback, проверка заголовков до тела, multipart в памяти, лимиты и сопоставление ошибок. Не принимать дополнительные части, не логировать данные, не использовать временные файлы. Проверить обработку HTTP-фрейминга и `Expect: 100-continue`; интеграция UI использует те же проверки `Host`.
5. Проверить API реальными HTTP-запросами, ошибки, приватность и параллельность; отдельно выполнить бенчмарк. Проверить браузером защиту от сторонних форм и preflight, затем `./scripts/check.sh`. Исправить ошибки автоматической проверки до завершения реализации.
