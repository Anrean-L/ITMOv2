# Модель данных: локальный анализ CSV

Источник требований: [spec.md](spec.md), [принятый контракт](../ui-backend-contract.md).

## Загрузка

- Единственная файловая часть `file`, исходные байты до 10 485 760 включительно; имя и MIME части не влияют на анализ или ключ.
- Временно находится в памяти; дискового сохранения и журналирования содержимого нет. Незавершённая загрузка прекращается и не создаёт результата.
- Ключ: SHA-256 всех оригинальных байтов, включая BOM и окончания строк; вычисляется после проверок безопасности и проверки лимита файла.

## Результат анализа

- `row_count`: неотрицательное число логических записей данных; `column_count`: число элементов `columns`.
- `columns`: упорядоченная последовательность `{name, missing_count}` по позициям заголовка, включая дубликаты и пустые имена. `name` — точная строка, BOM сохраняется; `missing_count` целое от 0 до `row_count`.
- Заголовок — первая логическая запись с хотя бы одним полем; все записи данных имеют одинаковую с ним ширину. Пустое значение — только строка нулевой длины. Строгие UTF-8 и CSV; 1000 колонок, 100 000 записей данных, 131 072 UTF-8 байта на распакованное поле включительно.
- Результат не содержит имя файла и не зависит от состояния другого запроса. Хранить неизменяемое значение или исключить мутацию между запросами.

## Ошибка

- Стабильный код, безопасное сообщение и объект `details`; 403 и 405 не обязаны использовать эту схему. Неправильная ширина содержит `record`, `expected_fields`, `actual_fields`; превышение лимита содержит `kind`, `limit`, `unit` согласно [контракту HTTP](contracts/http-api.md).
- Не содержит файл, пути, трассировки или частичный результат. Ошибки не кэшируются.

## Запись LRU и выполняющийся анализ

- Запись связывает ключ с успешным результатом и размером его JSON в UTF-8. Порядок меняется при попадании и добавлении. Вместимость: 128 записей и 16 МиБ суммарного сериализованного размера; слишком большой результат возвращается без сохранения.
- Под общей синхронизацией выполняются поиск, изменение порядка, вставка и вытеснение; разбор разных ключей не удерживает общую блокировку. Отдельное ожидание для каждого отсутствующего ключа: `нет → выполняется → успех/ошибка → удалён из выполняющихся`; успех при возможности попадает в LRU, ошибка сообщает всем ожидающим и допускает новый анализ. Кэши процессов независимы и пусты после перезапуска.
- Отказ безопасности не меняет кэш. Отмена одного ожидания не отменяет общее вычисление; успешная работа после ухода всех клиентов может завершиться и быть сохранена.
