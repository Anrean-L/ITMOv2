# Исследование решений UI

**Рамки**: проектирование, не реализация. Основание — [спецификация](spec.md), [контракт](../ui-backend-contract.md), конституция и существующий CLI. Блокирующих неопределённостей для планирования нет; сервер и команда его запуска ещё не существуют.

## Технология и размещение

**Решение**: статический HTML/CSS и нативный JavaScript под `src/csvpeek/web/`; сервер бэкенда отдаёт страницу с API на одном origin.

**Обоснование**: один экран, нет текущего фронтенд-стека, конституция требует простоты и минимальных зависимостей. Пользовательские данные и имена отображаются как текст.

**Альтернативы**: фреймворк и сборщик добавляют зависимости без выявленной необходимости; отдельный сервер UI усложняет согласованную same-origin модель. Точный способ выдачи ресурсов и команда запуска зависят от бэкенда и не являются новым API-контрактом.

## Запрос и обработка результата

**Решение**: относительный `POST /api/analysis`, `FormData` с одним файлом и обязательный заголовок `X-Csvpeek-Request: 1`; браузер формирует границу multipart. Код и доступные безопасные детали ошибок преобразуются в сообщения UI; 403, неверный JSON и сетевой сбой обрабатываются без доверия к телу.

**Обоснование**: это соответствует общему контракту; вручную заданный `Content-Type` может не содержать корректную границу. Проверять типы и инварианты ответа до отображения, не переопределяя семантику анализа.

**Альтернативы**: разбирать CSV в браузере — дублирование бизнес-логики; использовать серверное сообщение как HTML — угроза исполнения данных.

## Состояния и смена файла

**Решение**: явные состояния initial, selected, loading, success и error и идентификатор каждой попытки; новый выбор делает предыдущий ответ неактуальным. Отмена диалога сохраняет текущий выбор, повторный выбор того же файла поддерживается. Остановка ожидания не обещает отмены серверной работы.

**Альтернативы**: сопоставлять ответы по имени файла или порядку завершения недостаточно при повторном выборе и гонках; отдельная серверная операция отмены контрактом не требуется.

## Адаптивность и доступность

**Решение**: применить утверждённый стиль achromatic-ledger: нейтральная поверхность, выравненные цифры и список столбцов, без декоративных графиков; системные формы, подписи, индикатор фокуса и объявления состояния. Проверить заданные ширины, 200% масштаба, клавиатуру и диктор; сенсорные цели не менее 44 × 44 CSS px.

**Альтернативы**: широкая таблица с горизонтальной прокруткой страницы и управление только мышью противоречат спецификации. Физический телефон не сможет обратиться к `127.0.0.1` компьютера; тесты ширины не доказывают удобство на физическом устройстве.

## Проверка и зависимости

**Решение**: автоматизировать значимые проверки состояний и поведения запросов там, где доступен браузерный инструмент; при отсутствии стека описать ручные воспроизводимые проверки и отдельно указать, что не автоматизировано. Сквозной тест зависит от готового сервера, а существующий `./scripts/check.sh` проверяет только Python CLI.

**Альтернативы**: считать Python-тесты доказательством доступности UI нельзя; вводить библиотеку браузерных тестов без анализа её необходимости и доступности преждевременно. Численные тайм-ауты и ограничения параллелизма не согласованы и не являются блокером планирования.
