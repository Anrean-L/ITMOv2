# План реализации: браузерный анализ CSV

**Ветка**: `practice-5` (текущая; setup вернул идентификатор функции `001-csv-analysis-ui`) | **Дата**: 2026-10-27 | **Спецификация**: [spec.md](spec.md)

**Основание**: спецификация UI и [принятый общий контракт](../ui-backend-contract.md). Этот план описывает работу UI, не реализует её и не меняет контракт.

## Summary

Создать один доступный адаптивный экран для выбора локального файла, запуска анализа и просмотра точных результатов или понятной ошибки. Небольшой набор статических HTML, CSS и нативного JavaScript будет работать на том же origin, что локальный API; анализ остаётся ответственностью бэкенда. UI сохраняет текущий выбор и идентичность попытки, чтобы не отображать устаревшие ответы.

## Technical Context

**Language/Version**: HTML, CSS, браузерный JavaScript; существующее приложение — Python 3.12+.

**Primary Dependencies**: браузерные API, стандартная библиотека Python для существующего проекта; фреймворк, сборщик и новые обязательные зависимости не планируются. Шрифт Geist — при локально доступном ресурсе; системный sans-serif служит полноценной заменой без сетевой зависимости.

**Storage**: выбранный файл и UI-состояние в памяти текущей страницы; персистентное хранение отсутствует. Правила памяти и журналирования сервера определены контрактом.

**Testing**: `./scripts/check.sh` для регрессии CLI; проверки браузерных сценариев с контролируемыми ответами, затем сквозные проверки с фактическим локальным сервером и ручные проверки доступности. Инструмент автоматизации браузера выбирать только при обоснованной необходимости, не предполагая, что он уже установлен.

**Target Platform**: современный браузер; UI/API на одном origin `http://127.0.0.1:<порт>`. Планшетные и телефонные ширины проверяются изменением размеров окна; доступ с физического телефона к серверу компьютера не входит в область.

**Project Type**: один экран локального веб-приложения поверх существующего CLI/API.

**Performance Goals**: не вводить неподтверждённые ограничения времени; пользователю виден статус работы. По спецификации 9 из 10 участников выполняют сценарий за 2 минуты без времени анализа.

**Constraints**: принятый контракт, доступность клавиатуре и диктору, 320/390/768/1440 CSS px, масштаб 200%, ограничения файлов и отсутствие персистентного хранения. Сохранить существующий CLI.

**Scale/Scope**: один пользователь и выбранный файл; до 10 МиБ, 1000 столбцов, 100 000 записей и 128 КиБ на поле согласно контракту. История, экспорт и настройки CSV вне области.

## Constitution Check

**До и после проектирования: PASS**, при выполнении предусмотренных проверок; реализации и результатов тестов интерфейса пока нет.

1. **Сохранение поведения**: не менять существующий CLI; прогонять регрессионные тесты.
2. **Простота и зависимости**: нативные веб-возможности и существующая стандартная библиотека; дополнительная зависимость только с отдельным обоснованием.
3. **Независимая логика и согласованный контракт**: UI не разбирает CSV и использует принятый общий контракт. Изменения контракта требуют нового согласования.
4. **Успехи и ошибки**: план покрывает валидные и невалидные ответы, границы, доступность и гонки; перед завершением реализации обязательны проверки проекта.
5. **Детерминированность и явные ошибки**: исходный порядок, реальные нули и явные сообщения; некорректные ответы не показываются как успех.
6. **Конфигурация агента**: не менять существующие настройки, навыки и хуки. При реализации соблюдать AGENTS.md, инспекцию CSV и автоматическую проверку после правок через `apply_patch`.
