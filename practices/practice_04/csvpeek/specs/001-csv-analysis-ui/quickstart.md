# Руководство по проверке UI

Нужны Python 3.12+, Node.js для автоматических проверок UI и браузер. Сервер отдаёт UI и API на одном origin в соответствии с [общим контрактом](../ui-backend-contract.md). Запуск из корня репозитория:

```bash
PYTHONPATH=src python -m csvpeek.server --port 8000
```

Открыть `http://127.0.0.1:8000` на том же компьютере. Для остановки нажать Ctrl+C в терминале сервера.

## Регрессия существующего CLI

Из корня репозитория:

```bash
./scripts/check.sh
PYTHONPATH=src python -m csvpeek examples/people.csv
node --test tests/test_ui_success.js tests/test_ui_response.js tests/test_ui_errors.js tests/test_ui_retries.js
node --test tests/test_ui_live.js
```

Ожидаются успешные проверки и 4 строки, `name, age, score`, пропуски 0, 1, 0. Для `test_ui_live.js` сервер должен быть запущен; при другом порте задайте `CSVPEEK_TEST_URL`, например `CSVPEEK_TEST_URL=http://127.0.0.1:8743`. Node-проверки используют имитацию DOM; первые четыре файла используют контролируемые ответы, последний — настоящий API. Они не заменяют проверки в реальном браузере.

## Проверка после реализации UI и API

1. Запустить сервер по инструкции бэкенда и открыть `http://127.0.0.1:<порт>` на том же компьютере. Выбрать `examples/people.csv`, убедиться в имени, явно запустить анализ; ожидаются 4 строки, 3 столбца и 0, 1, 0 в исходном порядке.
2. Проверить CSV с `x,x` и записью `,1`: две отдельные позиции и 1, 0 пропусков. Проверить заголовок без строк, пустой заголовок-поле, BOM, длинные имена и полностью пустой столбец. Проверить пустой файл, неверную кодировку, кавычки и ширину записи: понятные ошибки без частичного результата.
3. Проверить границы размера и структуры, доступные подсказки, ответ 403, некорректный ответ и сетевой сбой; проверить восстановление повтором или новым выбором. С задержанным ответом файла A выбрать B и убедиться, что ответ A не меняет экран B. Отмена диалога и повтор того же файла сохраняют ожидаемое состояние.
4. Проверить клавиатуру, видимый фокус, экранный диктор и объявление состояний, 200% масштаб, контраст и цели 44 × 44; на 320, 390, 768 и 1440 CSS px убедиться в доступности всех действий и значений без горизонтальной прокрутки страницы. Проверка ширины окна не заменяет проверки на физических устройствах.
5. Совместно с бэкендом выполнить проверки `Host`, `Origin`, заголовка, CORS, отсутствия персистентных копий и пользовательских данных в журналах из раздела проверок контракта. Убедиться, что текущие CLI-тесты по-прежнему проходят.

При реализации инспектор CSV подтвердил пример; 52 проверки Python и Node-проверки с контролируемым DOM прошли. Локальный сервер отдал страницу и вернул ожидаемый ответ API для `people.csv`; проверка `test_ui_live.js` сравнила результаты UI и CLI для примера, повторяющихся имён и заголовка без строк. Vivaldi не ответил на запрос автоматического инспектора (тайм-аут `Page.enable`), поэтому работа в браузере, видимое отображение, размеры, экранный диктор и пользовательские испытания остаются неподтверждёнными. Для проверки диктором пройти все действия клавиатурой и убедиться, что статус и ошибка объявляются; зафиксировать браузер и диктор. Для проверки размеров измерить ширины 320, 390, 768 и 1440 CSS px, масштаб 200%, контраст, размеры целей и отсутствие горизонтальной прокрутки, включая длинные имена. Для контролируемых отказов и поздних ответов можно использовать Node-проверки выше; для сквозного сценария с реальным браузером требуется работающий браузер.
