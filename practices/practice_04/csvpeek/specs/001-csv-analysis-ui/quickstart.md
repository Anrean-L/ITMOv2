# Руководство по проверке UI

Это инструкция для будущей реализации, а не утверждение, что UI или сервер уже работают. Сейчас доступна только проверка существующего проекта. Нужны Python 3.12+, браузер и реализованный по [общему контракту](../ui-backend-contract.md) сервер, отдающий UI и API на одном origin. Команда запуска сервера ещё не определена; использовать инструкцию бэкенда после её появления, не подменяя сервер другим origin.

## Регрессия существующего CLI

Из корня репозитория:

```bash
./scripts/check.sh
PYTHONPATH=src python -m csvpeek examples/people.csv
```

Ожидаются успешные проверки и 4 строки, `name, age, score`, пропуски 0, 1, 0. Эти проверки не доказывают работу будущего UI.

## Проверка после реализации UI и API

1. Запустить сервер по инструкции бэкенда и открыть `http://127.0.0.1:<порт>` на том же компьютере. Выбрать `examples/people.csv`, убедиться в имени, явно запустить анализ; ожидаются 4 строки, 3 столбца и 0, 1, 0 в исходном порядке.
2. Проверить CSV с `x,x` и записью `,1`: две отдельные позиции и 1, 0 пропусков. Проверить заголовок без строк, пустой заголовок-поле, BOM, длинные имена и полностью пустой столбец. Проверить пустой файл, неверную кодировку, кавычки и ширину записи: понятные ошибки без частичного результата.
3. Проверить границы размера и структуры, доступные подсказки, ответ 403, некорректный ответ и сетевой сбой; проверить восстановление повтором или новым выбором. С задержанным ответом файла A выбрать B и убедиться, что ответ A не меняет экран B. Отмена диалога и повтор того же файла сохраняют ожидаемое состояние.
4. Проверить клавиатуру, видимый фокус, экранный диктор и объявление состояний, 200% масштаб, контраст и цели 44 × 44; на 320, 390, 768 и 1440 CSS px убедиться в доступности всех действий и значений без горизонтальной прокрутки страницы. Проверка ширины окна не заменяет проверки на физических устройствах.
5. Совместно с бэкендом выполнить проверки `Host`, `Origin`, заголовка, CORS, отсутствия персистентных копий и пользовательских данных в журналах из раздела проверок контракта. Убедиться, что текущие CLI-тесты по-прежнему проходят.

Для контролируемых отказов и поздних ответов потребуется тестовое окружение или средства браузера; их конкретная команда зависит от принятого при реализации тестового инструмента. Если сквозной сервер или необходимые средства недоступны, явно отметить непроверенные сценарии.
