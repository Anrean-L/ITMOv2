# Контракт UI и бэкенда csvpeek

**Статус: принят UI, бэкендом и владельцем продукта.** UI принимает контракт и уточнения защиты ниже; бэкенд подтвердил принятие в своём ревью; владелец подтвердил принятие и поручил зафиксировать его. Контракт не является реализацией и не изменяет исходные спецификации. Источники: [UI](001-csv-analysis-ui/spec.md), [бэкенд](002-csv-analysis-api/spec.md), [ревью UI](001-csv-analysis-ui/ui-review.md), [ревью бэкенда](002-csv-analysis-api/backend-review.md).

## Размещение и границы

- Приложение слушает только IPv4 `127.0.0.1`; UI открывается по `http://127.0.0.1:<порт>`, UI и API используют один origin. Аутентификация и поддержка нескольких пользователей не требуются.
- На другом устройстве `127.0.0.1` указывает на него самого. Адаптивность для телефона и планшета сохраняется как требование к экрану, но доступ к серверу на компьютере по сети не входит в эту модель.
- Исходное содержимое файлов и результаты не сохраняются персистентно. Успешные результаты, включая исходные имена столбцов, могут находиться в памяти процесса до вытеснения или завершения процесса. Файл и данные результатов не записываются в журналы; это необходимо обеспечить и для временных буферов и журналов среды запуска. Кэш — внутренняя деталь, не меняющая ответ.

## Защита локального сервиса

- На всех маршрутах, включая выдачу UI, сервер принимает только единственный корректный `Host` с адресом `127.0.0.1` и фактическим портом сервера. Отсутствующий, повторённый, некорректный или другой `Host` отклоняется. На стандартном HTTP-порту 80 отсутствие явного порта эквивалентно `:80`; `Forwarded` и `X-Forwarded-Host` для этой проверки не используются.
- Если `Origin` присутствует, допускается только origin собственного UI с HTTP-схемой, адресом `127.0.0.1` и тем же эффективным портом. `null`, другой адрес, порт или схема, некорректное или повторённое значение отклоняются. Отсутствие `Origin` допускается; стандартный порт учитывается, сопоставление по префиксу или суффиксу не используется.
- Для `POST /api/analysis` обязателен ровно один `X-Csvpeek-Request: 1`; отсутствие, повтор или другое значение отклоняются. Имя заголовка сравнивается без учёта регистра. UI добавляет заголовок к запросу.
- Проверки выполняются до чтения и разбора CSV, доступа к кэшу или изменения состояния. При нарушении любого правила, в том числе нескольких одновременно, сервер возвращает `403` без пользовательских данных; UI показывает безопасную общую ошибку и не зависит от формата тела. Остальные статусы применяются после проверок.
- Межсайтовые CORS-разрешения не выдаются, включая preflight `OPTIONS`; запрос с чужим origin получает `403`. Пользовательские данные и имена отображаются как текст, не как исполняемая разметка. Эти меры предназначены для браузерных запросов сторонних сайтов, не являются аутентификацией и не защищают от вредоносных локальных программ или скриптов в собственном origin.

## Запрос

`POST /api/analysis`, обязательный заголовок `X-Csvpeek-Request: 1`, тело `multipart/form-data` с ровно одной файловой частью `file`, содержащей исходные байты. Отсутствие файла, несколько файлов и любые дополнительные части — ошибка. Имя файла и его MIME-тип не определяют валидность содержимого; UI сохраняет и показывает имя своего выбора. После проверок безопасности при неподдерживаемом типе тела — `415`, для других методов — `405`.

Для первого варианта действуют лимиты, включительно: файл 10 МиБ (10 485 760 байт), 1000 столбцов, 100 000 записей данных, 128 КиБ (131 072 байта) на декодированное и распакованное значение поля, измеренное в UTF-8 байтах. UI может проверить размер файла до отправки; сервер проверяет все ограничения. Числовые значения можно пересмотреть при появлении оснований.

## Анализ и успешный ответ

Строгий UTF-8, разделитель — запятая, CSV-кавычки и их проверка соответствуют существующему CLI. Первая логическая запись — заголовок; последующие записи данных должны иметь столько же полей. Считаются записи данных, не физические строки; пустыми являются только поля нулевой длины. Пробелы и `NA` — значения. Пустые и повторяющиеся имена допустимы; пустой файл или запись заголовка без полей — ошибка. Заголовок без данных даёт ноль строк и нули пропусков. BOM в первом имени сохраняется, как в CLI.

Успех — `200`, `application/json; charset=utf-8`:

```json
{"row_count": 1, "column_count": 2, "columns": [{"name": "x", "missing_count": 1}, {"name": "x", "missing_count": 0}]}
```

`row_count`, `column_count`, `missing_count` — неотрицательные целые; число элементов `columns` равно `column_count`, каждый `missing_count` не больше `row_count`. `name` — исходная строка. Массив сохраняет порядок и дубликаты; отдельной позиции не требуется. UI показывает позицию начиная с 1 и пустое имя как «Без имени», не изменяя данные. Невидимый BOM UI обозначает текстовой пометкой «BOM» и сохраняет исходное имя; если имя состоит только из BOM, это не считается пустым заголовком. Результат не содержит имя файла: UI использует имя текущего выбора. Нарушение структуры или инвариантов ответа UI показывает как ошибку анализа.

## Ошибки

Ошибки приложения возвращают JSON вида `{"error":{"code":"invalid_structure","message":"...","details":{}}}` без частичных результатов, содержимого CSV, путей и трассировок. `code` стабилен, `message` может меняться, `details` — объект. UI сопоставляет код со своими понятными сообщениями и действиями и не выводит произвольное сообщение как разметку.

| Условие | HTTP | Код | Действие UI |
| --- | --- | --- | --- |
| Неверный multipart, отсутствующая или лишняя часть | 400 | `invalid_request` | Сообщить об ошибке отправки, предложить повтор. |
| Неподдерживаемый тип тела | 415 | `unsupported_media_type` | Сообщить об ошибке отправки, предложить повтор. |
| Превышен лимит | 413 | `limit_exceeded` | Назвать известный предел и предложить уменьшить файл. |
| Пустой файл или заголовок без полей | 422 | `empty_csv` | Объяснить причину, предложить выбрать исправленный файл. |
| Некорректный UTF-8 | 422 | `invalid_encoding` | Предложить сохранить файл в UTF-8. |
| Неверные кавычки или число полей | 422 | `invalid_structure` | Предложить исправить файл; показать безопасные подробности, если они есть. |
| Внутренний сбой | 500 | `internal_error` | Сообщить о сбое и предложить повтор. |

Для неверного числа полей `details` содержит целые `record`, `expected_fields`, `actual_fields`: запись считается от 1 с учётом заголовка. Для ошибки кавычек номер не гарантирован. Для `limit_exceeded` указываются `kind` (`file_bytes`, `columns`, `rows`, `field_bytes`), целое `limit` и `unit` (`bytes`, `columns`, `rows`); для неизвестного вида UI использует общее сообщение. Размер загрузки проверяется до разбора, прочие ошибки определяются первой обнаруженной причиной при чтении. Для 405 форма тела отдельно не определена.

Ответы вне приложения, неизвестные коды, невалидный JSON и отсутствие связи могут не соответствовать схеме: UI показывает общую понятную ошибку и предлагает повтор; для известного HTTP 413 можно сообщить о превышении размера без выдуманных подробностей. Доставка ответа при обрыве не гарантируется.

## Поведение интерфейса и отмена

Выбор файла сам по себе не запускает анализ. Во время запроса видны имя и статус; повторный запуск для текущего выбора недоступен, смена файла доступна. При смене выбора предыдущий результат и ошибка очищаются, а ответ предыдущей попытки игнорируется независимо от имён файлов. Повтор после ошибки — новый запрос. Обрыв во время загрузки прекращает её обработку; после полной загрузки прекращение ожидания не гарантирует остановку серверного анализа. Отдельная операция отмены не требуется; успешный результат завершившегося анализа может попасть в память кэша, ошибки и незавершённый анализ — нет.

UI сохраняет требования доступности и адаптивности исходной спецификации: доступные имена и фокус, управление клавиатурой, объявление статусов и ошибок, читаемые результаты и сенсорные цели. Проверка на реальных размерах и с вспомогательными технологиями остаётся задачей реализации.

## Проверки и вопросы реализации

1. Проверить успешный same-origin запрос с `Origin` и без него; отклонение отсутствующего, неверного или повторённого `Host`, чужого, `null`, неверного или повторённого `Origin`, отсутствующего, неверного или повторённого специального заголовка. Проверить другой порт и схему, атакующее DNS-имя, порт 80 и регистр имени заголовка.
2. Проверить в браузере, что чужая форма не проходит без заголовка, cross-origin preflight не разрешён, а same-origin запрос работает; отказ не запускает анализ и не меняет кэш, проверка `Host` действует и при выдаче UI.
3. Значения тайм-аутов и ограничения одновременной работы не определены и не блокируют принятие. Не вводить произвольные числа без оснований; сохранять понятную ошибку и повтор.
4. Подтвердить отсутствие персистентных временных копий и пользовательских данных в журналах, проверить границы лимитов, ошибки, BOM и поздние ответы. Мобильную и планшетную ширину проверить изменением размера окна браузера; доступ к серверу компьютера с физического телефона не предполагается.
