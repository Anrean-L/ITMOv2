# Reflection

Выполняя 4 практику, я настроил AGENTS.md, собственный MCP, skill и hook для codex, с помощью которого я реализовал cli для анализа csv таблиц.

Skill я использовал, чтобы зафиксировать последовательность действий агента. Вместо того, чтобы каждый раз подробно описывать процесс в промпте, как мы это делали в мастер-промпте на первой практике, можно задать workflow через skill. в данном случае примерно такой: исследовать csv через mcp, изменить код, добавить тесты, проверить результат. Codex действительно загрузил этот скилл и следовал инструкциям, прочитав их в самом начале работы

Изначально MCP не запустился из-за несовместимости используемого API с установленной версией python mcp sdk. codex попытался обойти это, вызвав ту же функциональность через python напрямую. Формально он получил нужный результат, но не через прямой вызов mcp tool, поэтому пришлось исправить сервер и перезапустить сессию Codex. после этого inspect_csv стал вызываться напрямую через mcp как для корректного файла, так и для ошибочного входа.

С hook тоже возникла проблема: первоначально он определял корень родительского git репозитория и поэтому искал скрипт проверки не в том каталоге. После исправления пути автоматическая проверка стала запускаться после изменений и возвращать результат агенту. Это полезнее, чем просить агента запустить тесты после изменений, так он получает обратную связь всегда и сразу.
