# Integration-проверки

| Связь компонентов | Что может сломаться | Как воспроизводим | Ожидаемый результат | Evidence |
|---|---|---|---|---|
| HTTP API ↔ валидатор входа | Неверный формат тела | POST /api/reviews с {} | 422 | Статус и тело ошибки |
| HTTP API ↔ лимитер размера | Длинный diff | POST /api/reviews с diff >20k | 413 | Статус 413 |
| Редактор секретов ↔ LLM клиент | Секрет уходит в prompt | POST с diff, где есть token=abc123 | В prompt нет сырого секрета; [REDACTED] | Захват отправляемого prompt |
| LLM клиент ↔ контроллер | Ошибка/timeout LLM | Стимулировать timeout/исключение | Контролируемый ответ по ADR: 200 OK; summary="Автоматическая заглушка: LLM недоступен/ошибка. Риски не оценены."; risks=[]; checks содержит LLM_ERROR/LLM_TIMEOUT | Тело ответа и статус |
| Контроллер ↔ формат ответа | Несоответствие OUT-1 | POST с корректным diff | JSON summary/risks/checks; дополнительные поля запрещены; порядок risks по file asc, line asc | JSON-схема валидна |

### OUT-1: проверка контракта

- Валидировать ответ по JSON-схеме: ключи summary/risks/checks присутствуют, дополнительные ключи запрещены.
- Проверить детерминированный порядок risks: по file asc, затем по line asc.
- Сохранить снапшоты JSON для сравнения между коммитами.

### OBS-1: проверка наблюдаемости

- Логи содержат только разрешённые поля: request_id, duration, status.
- Проверить, что содержимое diff и ответ модели (prompt/LLM output) отсутствуют в логах, включая ошибки.
- Дополнительно (вне OBS-1): метрики могут публиковаться как проектное решение — http_requests_total, llm_requests_total, api_request_duration_seconds, controlled_llm_fail_ratio.

### QA-1: подтверждение риска evidence

- Для каждого риска убедиться, что поле evidence присутствует и относится к одному из типов:
  - выдержка diff (фрагмент строки/контекста, подтверждающий риск);
  - ссылка/идентификатор правила репозитория.
- Риски без evidence должны отсутствовать в ответе (проверка фильтрации).
- Негативный сценарий: отправить кейс, где evidence присутствует, но не подтверждает риск (в выдержке diff отсутствует признак, правило не соответствует) → риск должен быть исключён.
