# E2E-проверки

| Сценарий пользователя | Предусловия | Действие | Наблюдаемый результат | Evidence |
|---|---|---|---|---|
| Позитивный | Сервис доступен; корректный JSON c `diff` ≤ 20000; тестовый LLM с задержкой 200 мс | Отправить POST /api/reviews с валидным diff | 200 OK; JSON с полями summary, risks(≤3 c file,line,evidence,risk; поле rule обязательно при evidence-на-правило и отсутствует при чистой выдержке diff; при комбинированном evidence rule обязателен), checks; порядок risks по file asc, затем line asc | Пока не выполнялось; сохранить ответ JSON и статус |
| Негативный | Сервис доступен; тело без поля `diff` | Отправить POST /api/reviews c `{}` | 422 Unprocessable Entity | Пока не выполнялось; сохранить статус и тело ошибки |
| Граничный | Сервис доступен; `diff` длиной ровно 20000 | Отправить POST /api/reviews с `diff` длиной 20000 | 200 OK; корректный JSON | Пока не выполнялось; сохранить длину diff, статус, JSON |
| Ошибка LLM | Сервис доступен; включена заглушка LLM с исключением/timeout | Отправить POST /api/reviews с валидным diff | 200 OK; JSON по ADR: summary="Автоматическая заглушка: LLM недоступен/ошибка. Риски не оценены."; risks=[]; checks содержит LLM_ERROR/LLM_TIMEOUT | Сохранить статус и полный JSON ответа |
| QA-1 evidence | Сервис доступен; корректный diff с несколькими потенциальными рисками | Отправить POST /api/reviews | В ответе присутствуют только риски с валидным evidence (фрагмент diff или правило репозитория); риски без evidence отсутствуют; если evidence — правило (включая комбинированный evidence), присутствует поле rule с идентификатором CASE.md; при чистой выдержке diff rule отсутствует | Сохранить полный JSON, проверить наличие/отсутствие рисков, тип evidence и значение rule |
| QA-1 negative | Сервис доступен; diff и входы подобраны так, что evidence присутствует, но не подтверждает риск | Отправить POST /api/reviews | Риск с неподлежающим evidence исключён; в ответе нет рисков с нерелевантным evidence | Сохранить полный JSON и отметить, какой риск был отфильтрован |
