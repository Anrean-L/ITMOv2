# Проблема и метрики

## Проблема

- Пользователь: разработчик/ревьюер, который хочет получить автоматический список рисков по PR.
- Ситуация: отправляет diff PR в сервис для анализа.
- Что происходит сейчас: сервис без валидации и ограничений пересылает сырой diff во внешний LLM и возвращает произвольный ответ; контракт ответа не соблюдён.
- Почему это мешает пользователю или бизнесу: риск утечки секретов (нарушение SEC-1), отсутствие отказа по размеру >20k (API-1), нестабильный формат ответа (OUT-1) усложняет автоматическую проверку/интеграцию; возможны таймауты/500 без контролируемого ответа (REL-1), что ломает пайплайн CI.
- Что не входит в задачу: изменение бизнес‑процесса ревью, интеграции с GitHub/merge‑ботами, переработка архитектуры вне описанных правил.

## Метрики

Выберите измеримые показатели, относящиеся к проблеме. Не используйте VTG, IRR, WACC, CSAT или другую метрику только ради названия.

| Метрика | Текущее значение или способ замера | Целевое изменение | Когда измеряем | Источник данных |
|---|---:|---:|---|---|
| Соответствие формату ответа (OUT-1) | Автотесты на схему ответа | Обязательно для всех соответствующих запросов | На каждом коммите и в CI | Юнит/интеграционные тесты |
| Отклонение длинных diff (API-1) | Интеграционный тест: diff >20k → 413 | Обязательно для всех соответствующих запросов | В релизе и мониторинге | Логи HTTP/метрики API |
| Инциденты утечки секретов в prompt (SEC-1) | Статистический аудит/интеграционный тест с фиктивными секретами | 0 | На коммите и в релизе | Локальные тесты; внутренний аудит |
| Ошибки LLM-вызова, завершающиеся контролируемым ответом (REL-1) | Интеграционный тест: симулировать timeout/ошибку | 100% ошибок → контролируемый ответ | В тестах и мониторинге | Тестовые заглушки; логи |

## Почему изменение метрики подтвердит решение проблемы

Повышение доли корректных ответов (OUT-1) подтверждает соблюдение контракта и пригодность для автоматизации.
Отклонение длинных diff (API-1) снижает риск перегрузки/ошибок и соблюдает правило входа.
Нулевая утечка секретов (SEC-1) устраняет главный риск безопасности.
Контролируемые ответы при ошибках LLM (REL-1) повышают надёжность и предсказуемость сервиса.
